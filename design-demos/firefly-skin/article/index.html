整理 Dinic、最小割与费用流的模板、思路和容易写错的细节。正文仍然沿用网站现有的 Markdown、KaTeX 与代码高亮能力。

讲解

最大流

Dinic 算法先通过 BFS 对残量网络分层，再使用 DFS 在层次图中寻找增广路。只允许从低层走到高层，因此每轮都能排除大量无效路径。

一条路径能够推进的流量，是路径上所有剩余容量的最小值。若路径为 $P$，则本次增广量为 $$\Delta f = \min_{e \in P} c_f(e).$$
  • 加边时同时添加正向边与反向边。
  • DFS 遇到汇点时返回当前可增广流。
  • 每轮 BFS 后重置当前弧数组 cur。
  • INF 应大于所有可能答案的总和，不要随手使用 1e9。

复杂度与容量

Dinic 在一般图上的理论最坏复杂度为 $O(V^2E)$。在二分图匹配等特殊网络中，实际表现通常更好。

$$\operatorname{Dinic}(V,E)=O\!\left(V^2E\right)$$

模板实现

下面保留当前网站的深色代码块、语言标识、复制和长代码折叠方式，只调整外层边框与页面配色。

cpp 
template <typename T>
struct Flow {
    const int n;
    const T inf = numeric_limits<T>::max();

    struct Edge {
        int to;
        T w;
    };

    vector<Edge> ver;
    vector<vector<int>> h;
    vector<int> cur, d;

    void add(int u, int v, T c) {
        h[u].push_back(ver.size());
        ver.push_back({v, c});
        h[v].push_back(ver.size());
        ver.push_back({u, 0});
    }

    T dfs(int u, int t, T f) {
        if (u == t) return f;
        T rest = f;
        for (int &i = cur[u]; i < h[u].size(); ++i) {
            int id = h[u][i];
            auto &[v, c] = ver[id];
            if (c && d[v] == d[u] + 1) {
                T pushed = dfs(v, t, min(rest, c));
                c -= pushed;
                ver[id ^ 1].w += pushed;
                rest -= pushed;
            }
        }
        return f - rest;
    }
};

二分图匹配

将源点连接左部点、右部点连接汇点，每条容量均设为 1，即可把最大匹配转化为最大流。建图方向决定了残量网络是否会允许非法选择。

边容量含义
$S \to L$1每个左部点最多匹配一次
$L \to R$1允许的匹配关系
$R \to T$1每个右部点最多匹配一次
